# ADR-0005：门牌号自带节点

- 日期：2026-10-30
- 状态：采纳

## 背景

早期设计把「门牌号」定成 6 字符房间码，节点靠另外一条路告诉对方：
要么对方自己在节点列表里挑一个，要么由房主单独发一次节点码。

实践里这条路很别扭：房主拿到 6 位码，必须先解释「在哪个节点」「你先去加一下这个节点」，
对方才能敲门。房间和节点是绑死的（`ADR-0002`），把两者拆开发，等于让用户手工拼一个协议字段。

## 决定

**门牌号就是完整邀请**：`<节点码>.<房间码>`。

- 房主界面显示这**一整串**，复制按钮复制的也是整串。
- 客户端收到整串时，用**串里写的那个节点**去查房间，而不是设置里当前选中的节点；
  顺手把该节点记进设置（下次可以直接用短码）。
- 节点列表退化为**发现工具**：方便挑一台延迟低的机器，不再是敲门的前置条件。
- 6 位房间码与 `<标签>.<房间码>` 仍然被接受，作为「已经加过这个节点」时的快捷写法。

## 代价

- 长度从 6 涨到约 35 字符。判断：可以接受——这串东西的存在形式就是复制粘贴。
- 房间码必须有分隔符，否则无法与节点码区分；`.` 保留为唯一分隔符。
- 客户端多一条规则：敲门时可能要**切节点**（`knock()` 里按邀请里的节点改写设置）。

## 不做

- 不做「短链/二维码」这类服务端映射：那需要一个中心服务，与不运营中心服务的原则冲突。
- 不缩短节点码（指纹是安全边界，见 `ADR-0002`）。
