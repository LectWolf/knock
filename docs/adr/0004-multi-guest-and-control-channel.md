# ADR-0004 一扇门多个人：控制通道、昵称、踢人、心跳续期

日期：2026-10-28　状态：已接受

## 背景

第一版把门写成"一条通道"（AGENTS.md 原文「一个房间一条通道」），运行起来立刻露出三个洞：

1. MC 服务端本来就是给多人玩的。三个朋友敲同一个门牌号，第二个人被挡在外面。
2. 节点把房间寿命写死成 10 分钟。十分钟后房主想加人，只能重新开门，门牌号变了，之前发出去的作废。
3. 房主无从知道谁进来了，也没法赶人；房客在房主那边没有任何身份。

根因是 `knock/1` 是**哑管道**：握手之后就是裸 TCP 字节流，没有自称、没有拒绝的余地。
所以"看到谁""踢谁""他叫啥"全都无处附着。

## 决定

### 1. 一扇门可以在线多人

门牌号指"门"，不指"一条连接"。每个房客各自建立一条独立通路，都路由到房主本机的同一个服务端口。
门牌号不变，人数由房主的 MC 服务端自己决定（我们不设上限，节点侧的房间数上限照旧）。

**这条**改掉了 AGENTS.md 的「一个房间一条通道」。新表述：
**一个房间只有一条"信令登记"，但可以有多条数据通路。**

### 2. 控制通道 `knock/2`

房客连上后先开一条小流，发一帧 JSON：

```json
{"proto": 2, "nickname": "小张", "app": "0.1.0"}
```

房主回一帧：

```json
{"ok": true}                                   // 放进来，后续数据流才开始
{"ok": false, "reason": "kicked"}              // 被踢过
{"ok": false, "reason": "version"}             // 协议版本不认
```

一帧一个连接，长度前缀，上限 512 字节——控制帧不该长，写死上限防滥用。
**数据流在 `ok` 之后才建立**，所以拒绝发生在传数据之前，不浪费带宽。

### 3. 昵称

首次启动时设（引导页），之后在设置里改。存在客户端本地，不注册、不上传。
房主列表里显示「昵称 · 通路（直连/绕路）· 已连时长」。

### 4. 踢人

踢 = 关闭该会话的连接 + 在**本房间**内记住他的 `EndpointId`。
他再敲同一扇门，控制帧直接被回 `kicked`；关门即忘，不落盘。
不做永久黑名单（要配管理界面，且容易变成"不小心把自己锁在外面"）。

### 5. 房间寿命跟着房主走

`announce` 兼作心跳：每 60 秒重发一次，节点以**最后一次心跳**为寿命起点。
房主关窗口 → 心跳停 → 60 秒内房间过期。
不再有"10 分钟到了"这种事：房主还在，门就一直开着；房主走了，门自然关。

### 6. 版本协商

自托管意味着**节点可能落后于客户端**，而且用户看不到版本号，只会看到"连不上"。
所以把版本写进协议，让不匹配变成一句人话：

- 节点 `GET /healthz` 与房间响应带 `proto: {api: 1, transport: 2}`；
- 客户端不认识 `api` 版本 → 拒绝该节点，提示"这个节点需要更新"；
- 房客控制帧版本不认 → 房主回 `version`，房客提示"对方的版本太旧"；
- 中继同理：`iroh-relay` 主版本必须与客户端一致，由节点配置里自报。

**不做**"尽力兼容"：半通比不通更糟，用户会以为是网络问题。

## 后果

- 房主侧需要一份会话列表（不再只是单一 `ConnState`）：状态机仍是"门"的状态，
  列表是"门里的人"。两者分开，不往 `ConnState` 里塞第八个状态。
- 控制帧是唯一的新攻击面：限长 512 字节、限一个连接一帧、超时 5 秒不回就关。
- 心跳意味着节点上有持续写入；60 秒一次可忽略。
