# 节点码 / 邀请串 格式 v1

这个文件是 `spec/invite-v1.tsv` 的人话版本。**两者冲突时以 TSV 为准**（测试只认它）。

实现：
- Rust：`client/src-tauri/src/invite.rs`（编 + 解）
- Go：`server/internal/invite/invite.go`、`server/internal/code32/code32.go`（编 + 解）
- 字符表只有一份，两边必须逐字节一致：`0123456789ABCDEFGHJKMNPQRSTVWXYZ`

## 为什么要有这个文件

节点码是**跨语言、跨版本、会被人手抄**的东西。任何一个字节的偏移、CRC 的多项式、
base32 的填充规则变了，全世界的码就同时失效。所以格式不写在代码注释里，写成带向量的规格。

## 字节布局（v1，多字节整数**小端**）

```
偏移  0        1        3          3+N        +2      +8     +1
     +--------+--------+----------+-----------+-------+------+-----+
     |ver|flg| label  |  地址…   |   port    |  pin  | crc |
     +--------+--------+----------+-----------+-------+------+-----+
```

| 字段 | 长度 | 规则 |
|---|---|---|
| `ver` | 高 4 bit | 固定 `1`。不认识就报错，不做兼容猜测 |
| `flg` | 低 4 bit | bit0 有 IPv4、bit1 有 IPv6、bit2 有域名、bit3 允许中转 |
| `label` | 2 | 节点自选标签，0..65535 |
| 地址 | 可变 | 顺序固定：IPv4(4) → IPv6(16) → 域名(1 字节长度 + ASCII) |
| `port` | 2 | 1..65535，0 视为非法 |
| `pin` | 8 | 节点 Ed25519 公钥的 SHA-256 前 8 字节 |
| `crc` | 1 | CRC-8/SMBUS 覆盖前面所有字节 |

**不变量**（都要有测试兜着）：
1. 至少有一个地址；一个都没有 = 无效码。
2. 域名必须纯 ASCII、非空、≤ 253 字节。
3. `port` 不能是 0。
4. 尾部不允许有多余字节；也允许多字节之后被截断。
5. CRC 对不上就拒绝——**不"尽力解码"**。

## 文本编码

- Crockford Base32：大写、无分隔符即规范形式。
- 解码时忽略 `-`、`_` 和空白；`O→0`、`I→1`、`L→1`；大小写不敏感。
- 尾部补出来的位必须是 0；不是 0 说明串被截断或拼接过，报错。

长度参考：仅 IPv4 = 18 字节 = **29 字符**；仅域名 = 32 字节 = 52 字符；
双栈 = 34 字节 = 55 字符。

> 这些码**不是给人手输的**，是复制/扫码用的。人手输的永远是 6 位门牌号。

## 邀请串

| 形态 | 例子 | 解析成 |
|---|---|---|
| 只有门牌号 | `A7K2M9` | `RoomOnly` |
| 短邀请 | `04HM.A7K2M9` | `Short { label, room }` |
| 完整邀请 | `34T15JR0E43VP08024H36H2NCSVPG.A7K2M9` | `Full { node, room }` |
| 只有节点码 | `34T15JR0E43VP08024H36H2NCSVPG` | `NodeOnly`（= 添加节点，不是敲门） |

解析规则：

1. 去掉所有空白。
2. 有 `.` 就以**第一个** `.` 切开：右边必须是 6 位合法门牌号；左边 4 个字符当标签，
   否则当节点码去解码（节点码最短 29 字符，撞不上）。
3. 没有 `.`：正好 6 位合法就当门牌号，否则当节点码。

**为什么用 `.` 分隔而不是定长拼接**：定长拼接要靠"先解两个字符拿到 flags，再算出节点码有多少字符"，
这套算术要在两种语言里各写一遍、而且一旦某位对不上就无声错位。多花一个字符换确定性，值得。
（这是对 ADR-0002 原设计的修正，已回写。）

## 短邀请的标签

`label` 是 16 bit，但短邀请里占 4 个字符 = 20 bit，所以高位补 4 个 0。
`0x0000 → "0000"`、`0xFFFF → "1ZZZ"`。解回来时超过 `0xFFFF` 就是错码，**不截断**。

## 金标向量

`spec/invite-v1.tsv`，13 列：`name label ipv4 ipv6 domain port pin_hex relay bytes_hex code room full_invite short_invite`。

- `bytes_hex` 是**不含任何编码**的原始字节，人可以肉眼核对布局；
- Rust 与 Go 的测试都读这一份文件；
- 重新生成：`cd client/src-tauri && cargo run --example gen_vectors > ../../spec/invite-v1.tsv`

改格式的正确流程：**先改 Rust → 重新生成向量 → 看 diff 是否就是你想改的那几处 → 改 Go**。
向量 diff 就是协议的 diff。

## 两个独立的锚点

除了向量，两边还各有一个**手算**的断言，防止"生成器和校验器一起错"：

- `CRC8("123456789") == 0xF4`（CRC-8/SMBUS 的标准检查值）
- `Encode([0x01, 0x02]) == "0410"`（16 bit 按 5 bit 分组的直接结果）
